# Taiga Backup Architecture

## Overview

The Taiga production environment uses a multi-layer backup strategy to provide both full-server recovery and application-level recovery.

The architecture consists of three backup layers:

1. **OVHcloud VPS Backup** — automatic daily backup of the VPS.
2. **Local Taiga Backup** — daily application-level backup stored on the VPS.
3. **Google Drive Off-site Backup** — external copy of the application-level backup.

## Architecture

```text
                    Taiga Production
                           │
              ┌────────────┴────────────┐
              │                         │
       OVHcloud VPS Backup       Application Backup
         Daily VPS backup               │
                                 ┌───────┴───────┐
                                 │               │
                            PostgreSQL         Media
                                 │               │
                                 └───────┬───────┘
                                         │
                                   Local validation
                                         │
                                      SHA-256
                                         │
                           ┌─────────────┴─────────────┐
                           │                           │
                    Local VPS Backup            Google Drive
                       14 days                    90 days
```

## Application Backup

The backup script is located at:

```text
/usr/local/sbin/taiga-backup.sh
```

Each execution:

1. Creates a PostgreSQL dump using `pg_dump` in custom format.
2. Validates the database archive using `pg_restore`.
3. Creates a compressed archive of the Taiga media Docker volume.
4. Validates the media archive.
5. Generates SHA-256 checksums.
6. Validates the local checksums.
7. Uploads the database, media, and checksum files to Google Drive using `rclone`.
8. Uses `rclone check` to verify that the local and remote files match.
9. Deletes local automated backups older than **14 days**.
10. Deletes Google Drive automated backups older than **90 days**.

If a critical step fails, the script exits with an error and removes incomplete files generated by that execution.

## Local Storage

Local backups are stored under:

```text
/var/backups/taiga/
├── database/
├── media/
└── checksums/
```

Example backup set:

```text
database/
  taiga-db-2026-10-02_04-10-22_UTC.dump

media/
  taiga-media-2026-10-02_04-10-22_UTC.tar.gz

checksums/
  taiga-2026-10-02_04-10-22_UTC.sha256
```

Local retention is **14 days**.

## Off-site Storage

Application backups are copied to Google Drive using the dedicated `rclone` remote:

```text
taiga-drive:
```

Remote structure:

```text
Taiga Backups/
├── database/
├── media/
└── checksums/
```

The Google Drive integration uses a dedicated Google OAuth application with the `drive.file` scope.

Remote retention is **90 days**.

## Scheduling

Backups are automated using systemd:

```text
/etc/systemd/system/taiga-backup.service
/etc/systemd/system/taiga-backup.timer
```

Check the timer:

```bash
systemctl status taiga-backup.timer
```

List the next scheduled execution:

```bash
systemctl list-timers taiga-backup.timer
```

Run a backup manually:

```bash
sudo systemctl start taiga-backup.service
```

## Monitoring and Logs

Check the most recent backup execution:

```bash
sudo systemctl status taiga-backup.service
```

View recent backup logs:

```bash
sudo journalctl -u taiga-backup.service -n 100 --no-pager
```

A backup is considered successful only after:

```text
Database dump created
        ↓
Database validated
        ↓
Media archive created
        ↓
Media archive validated
        ↓
SHA-256 generated and validated
        ↓
Files uploaded to Google Drive
        ↓
Remote files compared with local files
        ↓
Backup completed successfully
```

The logs should contain:

```text
Local backup validated successfully.
Google Drive backup validated successfully.
Taiga backup completed successfully.
```

## Recovery Strategy

Each backup layer addresses a different recovery scenario:

| Layer | Purpose | Retention |
|---|---|---:|
| OVHcloud VPS Backup | Full VPS/server recovery | Managed by OVHcloud |
| Local Taiga Backup | Fast database/media recovery | 14 days |
| Google Drive Backup | Off-site application recovery | 90 days |

The PostgreSQL dump allows the Taiga database to be restored independently of the original Docker volume.

The media archive contains uploaded files and attachments stored in the Taiga media Docker volume.

The Google Drive copy provides an additional recovery path if the VPS or its local storage becomes unavailable.

## Important Files

```text
/usr/local/sbin/taiga-backup.sh
/etc/systemd/system/taiga-backup.service
```

The `rclone` configuration contains OAuth credentials and **must not be committed to Git**.

Do not store OAuth tokens, Google Client Secrets, passwords, or other backup credentials in this repository.
